# Contributing a template

A template is a folder `templates/<slug>/` with:

- `template.json`: gallery metadata (slug equal to the folder name, title, category from `categories.json`, summary, takes, gives, icon, needs, targets; `source` with a licence on the allowlist when adapted).
- `SKILL.md`: the workflow in the Workflows format (`## Inputs`, numbered `## Steps`, `## Output`), with `name` and `description` in the frontmatter.
- `evals/evals.json`: `{"evals":[{"prompt","files","expectations"}]}`. The first entry is the gallery sample; `files` are paths inside the template.
- Optional `scripts/`, `references/`, `samples/`.

Rules checked by CI (`npx tsx tools/validate.ts`):

- At most 40 files, 2 MB per template, 1 MB per file. Relative paths, no `..`, no dotfiles, no symlinks.
- Workflow paths appear only as `/workspace/workflow/`, `/workspace/inputs/`, `/workspace/out/` and `/workspace/knowledge/`. `/workspace/inputs/` never appears inside a fenced code block. Every `/workspace/workflow/...` file must exist in the template.
- `needs.connections` and `needs.secrets` equal the SKILL.md frontmatter.
- No em-dashes in `SKILL.md` or `template.json`.
- Licences: Apache-2.0, MIT, BSD-2-Clause, BSD-3-Clause, CC-BY-4.0. Add one line per adapted source to `NOTICE`.

`catalog.json` is generated by CI. Never edit it by hand.
